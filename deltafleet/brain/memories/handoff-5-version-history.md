Scalability + robustness pass (**v0.14–v0.18**, ADR #25–#29, **120 tests**): `Ledger.state()` is now an **incrementally-maintained materialized view** (O(1) amortized reads vs the old full-replay-per-call; ~10.4s→0.1ms for 200 reads over a 150k-event log); `/api/state` is **memoized by a ledger `version` counter** so N console pollers + idle ticks collapse to one recompute per append; **confidence calibration folds incrementally** so it's off the run hot path (was an O(all-actions) scan inside the agent loop); the **metric-sample window is bounded** (`Ledger.SAMPLE_WINDOW`, count preserved); the ledger **loads crash-safely** (a torn final line from a crash mid-append is dropped and truncated from disk, not a boot failure; mid-file corruption still throws). Full ledger snapshot/segmentation is **deliberately deferred** (ADR #28) — the real bottlenecks are gone and doing it now would be premature bloat; the design is recorded for multi-year scale. The pass was verified by **three sub-agent reviews** (a scalability audit that produced the ranked worklist + two adversarial code reviews): no reachable bug in the materialized view; one real calibration-parity divergence in the confidence aggregate was caught and fixed (round `agreementRate` to 3dp before `calibrate()`, with a regression test) before it could ship.
